# AI API (MCP server with live editing) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An AI agent builds and edits a Paradox Diagram through a local MCP server while the person edits the same
diagram live at https://diagram.team2102.org, and the diagram gets fuse, gauge, IP, CAN bus and custom fields.

**Architecture:** A new `mcp/` workspace package (`@paradox2102/diagram-mcp`) holds the diagram in a file, applies AI
tool calls and tab edits in one order, and runs a WebSocket server on 127.0.0.1. The site connects to it from a
`#live=<port>.<token>` link. Both sides reuse `src/model`, `src/catalog`, `src/geometry` and `src/export`. Every
change from the tab travels as a `restore` action that carries a `DocPatch` (the items that changed), which also
gives the tab its selective undo.

**Tech Stack:** Vite 8, React 19.3, TypeScript 7, Vitest 5 (existing). New in `mcp/` only: `@modelcontextprotocol/sdk`,
`zod`, `ws`, `@resvg/resvg-js`. Liberation Sans TTF (SIL OFL 1.1) for the render.

**Spec:** `docs/specs/2026-10-28-ai-api-design.md`. Read it first. Section numbers below refer to it.

## Global Constraints

- Node 24 or later. ESM only. Pin every new dependency to an exact version, at least two weeks old on the install day.
- `npm run check` (type check and all tests, app and `mcp/`) must pass after every task.
- The diagram file stays `format: "paradox-diagram"`, `version: 1`. All new fields are optional.
- Live protocol number: `1`. Close codes: `4401` bad token, `4426` protocol mismatch. Bad Origin: HTTP `403` on upgrade.
- The server listens on `127.0.0.1` only. Token: 16 random bytes, base64url.
- Default site origin: `https://diagram.team2102.org`. `http://localhost:*` and `http://127.0.0.1:*` are always allowed.
- AI device and wire IDs: `^[A-Za-z][A-Za-z0-9_-]{0,39}$`, unique among all device and wire IDs.
- Render: at most 1600 px wide. `scale` 1 to 4.
- Field limits: `ip` IPv4 dotted quad or `DHCP`; `canBus` 1 to 20 characters; `fields` at most 20 rows, label 1 to 40
  characters, value at most 200; `fuseA` more than 0 and at most 200; `awg` integer 4 to 30, power wires only.
- The `mcp/` package version is always the root `package.json` version.
- Commits: Conventional Commits, author is the repo-local noreply address, no Claude attribution lines.
- Do not push, publish to npm, or release. Task 17 stops before the release; the user publishes.

## Decisions this plan adds to the spec

- **One action for all tab edits.** The canvas edits by gesture (`begin`/`preview`/`end`), not only by `Action`. So
  the tab sends every local change as `{ type: 'restore', patch: DocPatch }`, made by `diffDocs(before, after)`.
  The spec's `restore` fields (`devices`, `wires`, `remove`) are inside `patch`, with `added`, `title` and
  `hideTags`.
- **A patch cannot bring back what the other side removed.** `applyPatch` adds an item that is not in the diagram
  only when the patch lists it in `added`. Otherwise the server rejects the action, then sends the current `doc` to
  that tab, which reverts it.
- **Render font.** `exportSvg` uses `font-family="Helvetica, Arial, sans-serif"`. The render bundles Liberation Sans
  (metric-compatible with Arial, OFL) as the default font, not Barlow. This deviates from the spec's font list.
- **Docs source.** `node mcp/dist/server.js --dump-tools` prints the tool reference JSON. `npm run build` writes it
  to `public/api/tools.json` before `vite build`. A test compares the file with the live registry.

## Review Focus

1. **The person removes a device that the AI's next batch uses.** The op must fail with "no device "intake"; the
   devices are: …", not a crash. Test in Task 8.
2. **A tab reload during live mode.** The tab must connect again with the token kept in `sessionStorage`, with no
   second "Replace?" question. Test in Task 14.
3. **A relative or `~/` file path from the AI.** The path resolves against the server's working directory, and `~/`
   against the home directory. The result shows the absolute path. Test in Task 7.
4. **`--port` already in use.** The server prints `port 5199 is in use; start with --port 0 to pick a free port` to
   stderr and exits 1. Test in Task 13.
5. **`render` with a `region` outside the diagram, or a very large diagram.** A region outside gives an error with
   the content box. A large diagram lowers `scale` so that the width is 1600 px or less. Test in Task 11.

### Task 5: `DocPatch` and the `restore` action

**Files:**
- Create: `src/model/patch.ts`, `src/model/patch.test.ts`
- Modify: `src/model/actions.ts`

**Interfaces:**
- Produces:
  - `interface DocPatch { devices: Device[]; wires: Wire[]; remove: string[]; added: string[]; title?: string; hideTags?: boolean }`
  - `diffDocs(before: Doc, after: Doc): DocPatch`. An item that is new or changed in `after` goes into `devices` or
    `wires`, and `added` when it is new. An ID that is in `before` and not in `after` goes into `remove`. `title`
    and `hideTags` are set only when they changed. Compare items with a stable JSON comparison (the key order does
    not matter).
  - `isEmptyPatch(p: DocPatch): boolean`
  - `applyPatch(doc: Doc, p: DocPatch): { doc: Doc; error: string | null }`. The rules:
    1. Remove the `remove` IDs. Also remove the wires of a removed device.
    2. Replace each device or wire that has the same ID, in place, so the drawing order stays.
    3. Add an item that is missing only when its ID is in `added`. Otherwise give the error
       `<id> was removed by the other side` and the unchanged `doc`.
    4. Give the error `wire <id> ends at a device that is gone` for a wire whose device does not exist.
    5. Set `title` and `hideTags` when they are present.
  - `Action` gets `{ type: 'restore'; patch: DocPatch }`. `apply()` returns `applyPatch(...).doc`.

- [ ] **Step 1: Write the failing tests.**
  - `diff then apply gives the after doc`: for a move, a rename, an add, a delete (device with wires), a title change
    and a field change, `applyPatch(before, diffDocs(before, after)).doc` deep-equals `after`.
  - `undo patch keeps a later change by the other side`:
    1. The tab moves `intake`. `p = diffDocs(b, a)`.
    2. The AI renames `pdh` in `a`, which gives `a2`.
    3. `applyPatch(a2, diffDocs(a, b))` puts `intake` back and keeps the new `pdh` name.
  - `a patch does not bring back a device the other side removed`: an error and the doc unchanged.
  - `re-adding a device that the patch lists as added works`.
  - `the order of devices stays`.
- [ ] **Step 2:** Run `npx vitest run src/model/patch.test.ts` and check that it fails.
- [ ] **Step 3:** Write `patch.ts` and the action.
- [ ] **Step 4:** Run `npm run check` and check that all tests pass.
- [ ] **Step 5:** Commit `feat(model): document patches and the restore action`.

### Task 6: Live mode in the history

**Files:**
- Modify: `src/ui/useDocHistory.ts`
- Test: `src/ui/useDocHistory.test.ts`

**Interfaces:**
- Consumes: `diffDocs`, `applyPatch` and `restore` (Task 5).
- Produces: `useDocHistory(initial, opts?: { onLocal?: (before: Doc, after: Doc) => void })`. `DocHistory` gets:
  - `remote(doc: Doc): void`: sets `present` with no history step and no `onLocal`. During a gesture (between
    `begin` and `end`), it keeps only the newest doc and sets it at `end`. The gesture's own result is then applied
    on top of it with `applyPatch(newest, diffDocs(base, gestureResult))`.
  - `setLive(on: boolean): void`: on or off clears undo and redo.
  - `live: boolean`.

  `onLocal(before, after)` is called after each local commit (`change`, `replace`, `end`, `undo`, `redo`) when the
  doc changed. In live mode, undo and redo use a stack of `{ before, after }` steps (limit `HISTORY_LIMIT`):
  - undo applies `diffDocs(step.after, step.before)` to `present`;
  - redo applies `diffDocs(step.before, step.after)` to `present`.

  Out of live mode, the history works exactly as it does now.

- [ ] **Step 1: Write the failing tests.**
  - `onLocal gets each local change and not remote ones`.
  - `remote during a gesture waits for end and keeps the drag`: begin, preview a move, remote (rename X), end. The
    present has the move and the new name.
  - `live undo reverses only the local step`: local move A, remote rename B, undo. A is back and B keeps its new name.
  - `live redo`.
  - `setLive clears the stacks`.
  - The existing history tests pass unchanged.
- [ ] **Step 2:** Run `npx vitest run src/ui/useDocHistory.test.ts` and check that the new tests fail.
- [ ] **Step 3:** Change the hook.

### Task 13: Live WebSocket server

**Files:**
- Create: `mcp/src/live.ts`, `mcp/src/live.test.ts`
- Modify: `mcp/src/server.ts`, `mcp/src/tools.ts` (`open_in_browser`)

**Interfaces:**
- Consumes: `DiagramStore`, `applyPatch`, `src/live/protocol.ts`.
- Produces:
  - `startLive(store: DiagramStore, opts: { port: number; site: string }): Promise<LiveHandle>`
  - `interface LiveHandle { port: number; token: string; link(): string; clients(): number; close(): Promise<void> }`
  - `link()` returns `` `${site}/#live=${port}.${token}` ``.
- Behaviour:
  - Use `ws` `WebSocketServer` with `noServer`, on a `node:http` server bound to `127.0.0.1`. The path is `/live`.
  - On upgrade, check Origin: it must equal `site`, or match `^http://(localhost|127\.0\.0\.1)(:\d+)?$`. Else
    answer `HTTP/1.1 403 Forbidden` and destroy the socket.
  - First frame `hello`:
    - a wrong token closes with 4401;
    - a wrong `protocol` sends `error` and closes with 4426;
    - a good `hello` gets `welcome`.
  - An `action` frame (a `restore` patch): `applyPatch(store.doc, patch)`.
    - On an error, send `reject` with the error, then a `doc` to that client.
    - Otherwise `store.commit(next, 'tab', seq)`.
  - `store.onChange` sends a `doc` to every client. `seq` goes only to the client that sent it.
  - A port that is in use (`EADDRINUSE`) prints `port <n> is in use; start with --port 0 to pick a free port` and
    exits 1 (Review Focus 4).
  - `open_in_browser` opens `link()` with `open` (macOS), `xdg-open` (Linux) or `cmd /c start ""` (Windows) through
    `spawn` with an argument array (no shell string), and returns the link.

  - `good hello gets welcome with the doc and rev`.

  - `a tab action is applied and both clients get the doc; only the sender gets seq`.
  - `an AI commit reaches both clients`.
